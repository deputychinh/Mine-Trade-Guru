Architecture overview

I started from requirements, not the stack. The functional list is iBoard's: board tabs per exchange and instrument type, 3-level order book, foreign flow, session status, symbol detail with candles and a trade tape, watchlists and alerts. The non-functional list is what shaped the design: a price change has to reach the screen within 100 ms, the board has to hold 60 fps with 1,500 symbols updating 5 times a second, and memory must stay flat over a full trading day. Each of those targets maps to a specific decision in the plan (§4), so nothing is there just to look clever.

Data flows one way. The backend sends small delta frames in 100 ms batches, and every quote carries a version that goes up by one on each change. The socket lives in a Web Worker, which validates each frame, merges the deltas and picks out trades for the open symbol, all off the main thread. The worker posts at most one patch every 50 ms, the main thread merges whatever arrived into one store update per animation frame, and candles are built from those trades. Quotes sit in a `shallowRef` map, rows are virtualized and `v-memo`'d on the quote object, and the flash is a CSS class, so a tick re-renders one row and nothing else. If a version is skipped, or the server says it had to drop frames, the client re-fetches the snapshot rather than guess.

The code follows Vue Patterns: pages and a few containers touch stores and side effects, and everything else is presentational. Stores are Pinia Setup Stores and only actions change state. Feature code uses `components/base/*` wrappers, not raw Vuetify tags.

I checked SSI's FastConnect Data API. It exists and uses the channel codes this project copies (`X`, `F`, `R`, `MI`; bars come from trades instead of `B`), but credentials need a branch visit or KYC. So the backend is a simulator speaking SSI's format, and it sits behind a `MarketDataSource` interface in the backend. When credentials exist, a real adapter goes into the backend as a relay, so the secret never reaches the browser, and the UI doesn't change.

Vuetify 4 with its md3 blueprint covers Material Design 3, including light and dark schemes, so there's no Tailwind or Bootstrap on top. The five Vietnamese price colors (ceiling, floor, reference, up, down) are theme tokens tuned separately for each scheme to pass WCAG AA, and they always come with an arrow marker so color is never the only signal.
